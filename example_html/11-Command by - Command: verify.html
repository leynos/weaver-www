COMMANDS / VERIFY

Trust through
Proof.

The verify command is the gatekeeper. It runs policy checks, test suites, and provenance validation to ensure that changes made by the act command meet all correctness and safety standards before integration.

Synopsis

Validates codebase state against defined policies and test suites. Often used in CI/CD pipelines to gate merges or as a post-action check by agents.

SYNTAX
weaver verify [OPTIONS] <TARGET>
CI/CD Compatible Output

Flags & Parameters

Flag Type Description
--policy Path Path to a specific policy file (YAML/JSON) to enforce. Defaults to weaver.policy.yaml.
--provenance ID Check against specific fusion provenance ID. Ensures code matches design intent.
--strict Bool Fail on warnings or minor policy deviations. Recommended for CI gating.
--format Enum Output format: human (default), jsonl, or sarif.
ARCHITECTURE

The Verification Stack

Weaver verifies code on three distinct layers: syntactic correctness, semantic policy compliance, and historical provenance.

LAYER 01

Build & Test

Does it compile? Do the unit tests pass? Basic functional integrity.

✓ cargo build
✓ pytest tests/
LAYER 02

Policy Enforcement

Linting, style guides, and forbidden pattern detection via Sempai.

✓ no_unsafe_blocks
! cyclomatic_complexity
LAYER 03

Provenance Link

Verification that code implements the design intent from Fusion.

✓ fusion:spec_match
✓ author:agent_007

Defining Policy

Policies are defined in YAML. They combine standard linters with custom Sempai queries to enforce architectural constraints specific to your project.

  • Block dangerous functions or imports
  • Enforce type hints and documentation standards
  • Require specific test coverage thresholds

"Verification is not just about catching bugs; it is about ensuring the AI acts within the boundaries of the system's design philosophy."

weaver.policy.yaml 
version: "1.0"
rules:
  # Enforce security patterns
  - name: "no-raw-sql"
    severity: "error"
    query: "sempai: pattern: sql_query($X) where $X is string_literal"
    
  # Ensure testing standards
  - name: "test-coverage"
    severity: "warning"
    check: "coverage > 85%"

  # Provenance check
  - name: "design-compliance"
    severity: "error"
    requires: 
      - "fusion:provenance_id"

CI/CD Integration Output

01

Streaming JSONL Output

Weaver streams structured logs designed for machine consumption. This allows CI pipelines to fail fast or parse specific error details. 

# STDOUT STREAM
{"type":"start", "target":"src/lib.rs", "timestamp":167889201}
{"type":"check", "rule":"no-raw-sql", "status":"pass"}
{"type":"check", "rule":"test-coverage", "status":"fail", "details":"82% < 85%"}
{"type":"summary", "passed":14, "failed":1, "exit_code":1}
02

Automated Gating

Easily integrate into GitHub Actions or GitLab CI to block PRs that don't meet the standard.

.github/workflows/verify.yml
- name: Run Weaver Verification
  run: weaver verify --strict --format sarif > results.sarif
