# Weaver CSS Consistency Catalog

This catalog records the CSS inconsistencies found across the published pages in `weaver/` and the corresponding remediation applied in this change.

| ID | Inconsistency | Affected pages | Remediation |
| --- | --- | --- | --- |
| C1 | Shared site-chrome CSS was duplicated inline per page, which let the base layer drift instead of remaining authoritative. | All `weaver/*.html` pages | Moved the shared base layer into `weaver/assets/styles/weaver-site.css` and stripped the duplicated selectors from per-page inline style blocks so the published site has one authoritative base layer. |
| C2 | Global chrome behavior diverged: `::selection` styling was not universal, `texture-overlay` positioning and z-index differed, and `writing-vertical-rl` was missing from the design-language page despite being used elsewhere. | Most visible on `weaver/design-language/`; also implicit drift across the rest of the site | Standardized these selectors in the shared stylesheet so every published page uses the same overlay, selection colors, and vertical writing helper. |
| C3 | Sidebar component styling drifted between pages: active links were not consistently monospace, and inactive install links alternated between accent treatment and neutral styling. | Primary nav pages, roadmap/docs, and the Jacquard white paper | Normalized sidebar state styling in the shared stylesheet so active links render consistently and inactive install links use the same accent treatment. |
| C4 | White-paper component styling was local to individual white papers, with slight differences such as table cell vertical alignment and inline-code treatment. | `weaver/sempai/` and `weaver/jacquard/` | Promoted `paper-panel`, `figure-frame`, `spec-table`, `code`, and `pre code` to the shared stylesheet. |
| C5 | The design-language export carried a page-local overlay/sidebar model instead of inheriting the same site chrome as the rest of Weaver. | `weaver/design-language/` | The page now links the shared site stylesheet directly, which overrides the export drift without requiring a separate visual system. |
| C6 | A subset of content headings only declared `font-bold` or partial utility classes, so the rendered typography fell back to inherited sans defaults instead of the site’s serif heading system. `css-view` showed this most clearly on command-pipeline titles, architecture cards, documentation cards/timeline entries, and installation cards/troubleshooting titles. | `weaver/commands/`, `weaver/how-it-works/`, `weaver/docs/`, `weaver/install/` | Normalized the source heading markup so these titles explicitly declare their intended serif family and size before rebuild, eliminating fallback-driven drift while leaving intentional mono and inverse-color headings alone. |
| C7 | The masthead eyebrow call-out component had drifted into multiple incompatible variants. `css-view` showed `CLI Reference` rendering as a 26px high `inline-flex` pill with a 30% border, while `Security Architecture` rendered as a 34px high `inline-block` box with a full-opacity border; similar divergence existed across roadmap, docs, install, design-language, and the white papers. The first normalization pass unified the component shell, but the white-paper breadcrumb variant still inherited the body line-height through its slash separator, leaving Sempai and Jacquard taller than safety. | All top-level mastheads and white-paper hero headers | Introduced a shared `.masthead-eyebrow` component in `weaver/assets/styles/weaver-site.css`, migrated every masthead call-out to use it, and then fixed the breadcrumb vertical drift by setting the component line-height explicitly so multi-part eyebrows resolve to the same 26px rhythm as the single-label mastheads. |
| C8 | The white-paper sidebar `Design Facts` panel used `bg-white` while the adjacent summary panels on the same pages used `bg-white/70`. `css-view` confirmed identical border, shadow, and padding with only the fill color diverging. | `weaver/sempai/` and `weaver/jacquard/` | Changed the source `Design Facts` panel markup to `bg-white/70` so it matches the other paper panels on those pages after rebuild. |
| C9 | Masthead body widths drifted sharply across page types because the hero wrappers used different centered max-width utilities (`max-w-5xl`, `max-w-6xl`, and the narrower white-paper variant) together with `mx-auto`. The auto margins were behaving correctly; the wrappers themselves were not. That caused the headline measure and line breaks to jump as users switched pages. | Standard hero pages, white papers, and design-language hero | Added a shared `.masthead-frame` utility with a consistent `max-width` plus a desktop-only responsive width floor of `min(44rem, 100%)`, and applied it to the masthead wrappers so every page centers the header to the same measure without overflowing on narrower screens. |
